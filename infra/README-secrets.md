# ADA secrets — bootstrap, rotation, and what is committed

Every credential in this stack is generated by a script. Nothing is typed by
hand, nothing has a default worth guessing, and nothing real reaches git.

Two scripts do the work:

| script | language | what it owns |
|---|---|---|
| `infra/scripts/gen-env.mjs` | Node ≥ 18, no dependencies | `infra/compose/.env` — every variable the 11 services read |
| `infra/scripts/create_users.py` | Python 3, standard library only | Keycloak users and their realm roles |

Neither ever prints a secret. They report paths and variable names; you open
the file to see a value.

---

## 1. Bootstrap a fresh environment, in order

```bash
# 1. Generate infra/compose/.env. Creates what is missing, keeps what already exists,
#    and backs the file up before touching it.
node infra/scripts/gen-env.mjs

# 2. Prove nothing generic survived. Non-zero exit if anything is a
#    placeholder, too short, missing, or internally inconsistent.
node infra/scripts/gen-env.mjs --check

# 3. Fill in whichever external credentials you actually need. All start
#    empty and all are optional — see section 6.
$EDITOR infra/compose/.env

# 4. Start the stack. Keycloak imports realm-ada.json on FIRST start only.
cd infra/compose && docker compose up -d && cd ../..

# 5. Create the four ICMS realm roles, then apply what the import cannot hold
#    (master frontendUrl, APP_ORIGIN on ada-web, the ada-api secret file).
set -a; source infra/compose/.env; set +a
./infra/keycloak/create-icms-roles.sh
./infra/keycloak/apply-realm-config.sh

# 6. Build the roster, then create the people and assign their roles.
cp infra/users.example.yaml infra/users.yaml
$EDITOR infra/users.yaml
python3 infra/scripts/create_users.py --dry-run
python3 infra/scripts/create_users.py

# 7. Hand out the credentials from the file it names, then delete that file.
```

Step 5 is not optional even though `realm-ada.json` declares the same four
roles. `--import-realm` uses `IGNORE_EXISTING`: once the realm is in the
database, edits to the JSON do nothing. The two scripts are what make a
*live* realm match the file. `infra/keycloak/README.md` lists what only
`apply-realm-config.sh` can set. ada-web direct grants, the ada-api client,
the ada-field client and the session lifetimes are now in the JSON as well.

Step 6 closes the gap that script leaves — it creates the roles and assigns
them to nobody, printing an `add-roles` command for you to run once per
person. `create_users.py` does the assigning.

## 2. What is committed, and what is generated

| path | in git? | what it is |
|---|---|---|
| `infra/compose/.env.example` | **yes** | Template. Every variable, its class, a description, a placeholder. Never a real value. Regenerate with `--example`. |
| `infra/users.example.yaml` | **yes** | Sample roster covering all four roles. Fictional people, `.invalid` addresses, no credential field. |
| `infra/scripts/*` | **yes** | The generators themselves. |
| `infra/keycloak/realm-ada.json` | **yes** | Realm definition. `${VAR}` substitutions only, never a literal secret — see section 5. |
| `infra/compose/.env` | **no** | The real thing. Mode 0600. |
| `infra/compose/.env.backup.<ISO8601>` | **no** | Written before any change to `.env`. |
| `infra/users.yaml` | **no** | The real roster. No credentials, but real names, addresses and phone numbers. |
| `infra/secrets/user-credentials-<UTC>.txt` | **no** | Generated login credentials, mode 0600. Delete after delivery. |

The ignore rules are at the top of `.gitignore`. Verify any path with:

```bash
git check-ignore -q infra/secrets/anything.txt && echo ignored || echo TRACKABLE
```

## 3. Classification

`gen-env.mjs` sorts every variable into one of three classes, and `--check`
enforces the first two:

- **secret** — generated with `crypto.randomBytes`, base64url. Present only in
  `infra/compose/.env`.
- **config** — a setting, not a credential. Safe to read aloud, and committed
  to `.env.example` verbatim.
- **external** — issued by a third party. Generated **empty**, with a comment
  saying what it is and where to get one. Inventing a value would be worse
  than leaving it blank: the service would start, then fail at the first call.

### Why base64url

Generated values pass through four layers that each have an opinion about
punctuation, so the alphabet is chosen by elimination:

| excluded | because |
|---|---|
| `$` | Docker Compose expands `${...}` |
| `#` | starts a comment in a dotenv file, truncating the value |
| quote, double-quote, backslash, backtick, `!`, `*` | quoting, escaping and globbing under `set -a; source .env` |
| `@ : / ? % &` | structural in a URI — and two variables are embedded in one. `ADA_REDIS_URL` is `redis://:${REDIS_PASSWORD}@redis:6379/0`, and the database URLs embed `POSTGRES_PASSWORD`. An `@` in the password re-parses the URL into the wrong *host*, so the symptom is a connection error rather than an authentication error, which sends you looking in entirely the wrong place. |
| `+ / =` | plain base64's extras — all three are URI-structural or padding. This is exactly why base64url (RFC 4648 §5) exists. |

What survives is `A–Z a–z 0–9 - _`, unquoted, everywhere. The cost is 6 bits
of entropy per character instead of about 6.55; the fix is length, which is
free.

### Lengths

| bytes | bits | used for | why |
|---|---|---|---|
| 24 | 192 | database passwords, the Keycloak admin password, the three OAuth client secrets | Far past any offline attack, and stronger than the 128-bit secret Keycloak generates for a confidential client on its own. |
| 32 | 256 | `ADA_OTP_HMAC_KEY`, `ML_SERVICE_TOKEN` | Used as cryptographic keys, not compared as strings. HMAC-SHA256 gains nothing above 256 bits and loses security below it. |

User credentials are separate. `create_users.py` generates 20 characters from
a larger alphabet that includes punctuation, because the realm's own policy
demands `length(12) upperCase(1) lowerCase(1) digits(1) specialChars(1)`. A
base64url value would be rejected for having no special character.

## 4. Rotation — and what restarts

Rotation is always explicit and one variable at a time. Nothing rotates
implicitly, because a new value in `.env` does not reach a container that is
already running.

```bash
node infra/scripts/gen-env.mjs --rotate REDIS_PASSWORD
```

That backs up `.env`, replaces exactly that one value, and leaves every other
value untouched. Then:

| variable | what must be recreated | extra step |
|---|---|---|
| `POSTGRES_PASSWORD` | `postgres`, `ada-api`, `ada-ml`, `ada-notify`, `ada-worker`, `notify-migrate` | The password inside the running database does **not** change. `ALTER ROLE ... PASSWORD` it first, or every service authenticates with a value PostgreSQL has never heard of. |
| `REDIS_PASSWORD` | `redis`, `ada-auth`, `ada-worker` | Pending one-time codes and queued deliveries survive; the connections do not. |
| `KC_BOOTSTRAP_ADMIN_PASSWORD` | nothing | Only read on Keycloak's **first** start. Changing it later changes nothing — rotate that account in the admin console instead. |
| `ADA_OTP_HMAC_KEY` | `ada-auth` | Every pending one-time code becomes unverifiable. Rotate when nobody is mid-login. |
| `ML_SERVICE_TOKEN` | `ada-api` **and** `ada-ml`, together | Both read the same variable. Recreate them in one command or every job submission 401s in between. |
| `ADA_NOTIFY_CLIENT_SECRET`, `ADA_AUTH_CLIENT_SECRET`, `ADA_ML_CLIENT_SECRET` | the owning service | **Also needs a live-realm update — see section 5.** |

Recreating means `docker compose up -d --force-recreate <name>`. Plain
`restart` re-runs the existing container with its existing environment, and
will look exactly like the rotation silently failed.

## 5. The realm file, and the client secrets

`infra/keycloak/realm-ada.json` is tracked in git, so no literal secret may
live in it. **It already contains none.** All six credential-shaped fields are
environment substitutions:

- `ADA_NOTIFY_CLIENT_SECRET`, `ADA_AUTH_CLIENT_SECRET`, `ADA_ML_CLIENT_SECRET`
  — the three confidential service-account clients
- `ADA_GOOGLE_CLIENT_SECRET`, `ADA_GITHUB_CLIENT_SECRET` — identity providers,
  both `enabled: false`
- `KC_SMTP_PASSWORD` — realm mail

`ada-api` is the exception. The JSON declares the client with no secret, so
Keycloak generates one on import. `apply-realm-config.sh` writes it to
`infra/secrets/keycloak/ada-api-client-secret` (0600) and never prints it.
Copy it into `.env` as `ADA_API_CLIENT_SECRET`.

**Decision: keep substitution, do not strip.** Keycloak 26.7.2 resolves
`${NAME}` and `${NAME:default}` during a realm import from the container
environment, which `docker-compose.yml` supplies. The `${env.NAME}` form does
**not** work here — do not "fix" the file to it. Stripping the fields and
setting them after import would give a realm that imports but cannot
authenticate until a second script had run correctly; substitution keeps the
file complete and declarative while keeping every value outside git. Upstream
has a long history of bugs in this specific area (keycloak issues #12069,
#20199, #26275), so the behaviour is version-specific and worth re-verifying
on any Keycloak upgrade.

### The catch, and it is a real one

`--import-realm` is `IGNORE_EXISTING`. Once the realm is in the database the
JSON is never read again. So rotating a client secret in `.env` updates what
Keycloak would import *on a fresh volume* and changes nothing about the realm
you are actually running.

To rotate a live client secret, set it in Keycloak directly. Read these, then
run them yourself:

```bash
set -a; source infra/compose/.env; set +a

docker exec ada-keycloak /opt/keycloak/bin/kcadm.sh config credentials \
    --server "http://localhost:${KC_HTTP_PORT:-8090}${KC_HTTP_RELATIVE_PATH:-/idp}" \
    --realm master \
    --user "$KC_BOOTSTRAP_ADMIN_USERNAME" \
    --password "$KC_BOOTSTRAP_ADMIN_PASSWORD"

# Find the client's internal id (an id, not a secret)
docker exec ada-keycloak /opt/keycloak/bin/kcadm.sh get clients \
    -r "${ADA_REALM:-pcsmcpl}" -q clientId=ada-ml --fields id,clientId

# Set the secret to the value now in .env
docker exec ada-keycloak /opt/keycloak/bin/kcadm.sh update "clients/<ID>" \
    -r "${ADA_REALM:-pcsmcpl}" -s "secret=$ADA_ML_CLIENT_SECRET"

# Recreate the service that uses it
cd infra/compose && docker compose up -d --force-recreate ada-ml
```

Substitute `ada-notify` / `ADA_NOTIFY_CLIENT_SECRET` or `ada-auth` /
`ADA_AUTH_CLIENT_SECRET` as needed. `ada-notify`'s secret is also what
`ada-worker` reads as `ADA_ADMIN_CLIENT_SECRET`, so recreate `ada-worker` too.

## 6. External credentials

All start empty. Each matters only if you turn its feature on.

| variable | where to get one | needed when |
|---|---|---|
| `ADA_TWOFACTOR_API_KEY` | 2factor.in dashboard → API key | `ADA_SMS_PROVIDER=twofactor` |
| `HF_TOKEN` | huggingface.co → Settings → Access Tokens (read scope) | `SAM_BACKEND=sam3` (gated repo) |
| `ADA_GOOGLE_CLIENT_ID` / `_SECRET` | Google Cloud → APIs & Services → Credentials → OAuth 2.0 Client ID (Web application) | enabling the `google` identity provider |
| `ADA_GITHUB_CLIENT_ID` / `_SECRET` | GitHub → Settings → Developer settings → OAuth Apps | enabling the `github` identity provider |
| `KC_SMTP_USERNAME` / `_PASSWORD` | your mail relay | replacing mailpit for realm mail |
| `ADA_SMTP_USERNAME` / `_PASSWORD` | your mail relay | replacing mailpit for notifications |
| `ADA_AUTH_SMTP_USERNAME` / `_PASSWORD` | your mail relay | replacing mailpit for email one-time codes |

Whenever you set an SMTP password, set the matching `_STARTTLS=true` in the
same edit. Mailpit refuses STARTTLS so the defaults are `false`, and pointing
a real relay at a `false` sends the password across the wire in clear.

## 7. The pre-commit check

`--check` is what makes "not the generic one" enforceable rather than
remembered. Wire it in so a placeholder cannot be committed:

```bash
cat > .git/hooks/pre-commit <<'HOOK'
#!/usr/bin/env bash
set -euo pipefail

# 1. Nothing secret-bearing may be staged.
staged=$(git diff --cached --name-only)
if echo "$staged" | grep -qE '^infra/(\.env$|\.env\.|secrets/|users\.yaml$)'; then
  echo "refusing: a secret-bearing file is staged." >&2
  echo "$staged" | grep -E '^infra/(\.env$|\.env\.|secrets/|users\.yaml$)' >&2
  exit 1
fi

# 2. The realm file must carry no literal credential.
if echo "$staged" | grep -q '^infra/keycloak/realm-ada.json$'; then
  if git show :infra/keycloak/realm-ada.json \
     | grep -qE '"(secret|password)"[[:space:]]*:[[:space:]]*"[^$"]'; then
    echo "refusing: realm-ada.json has a literal secret; use \${VAR} instead." >&2
    exit 1
  fi
fi

# 3. If infra/compose/.env exists, it must not be generic.
if [ -f infra/compose/.env ] && ! node infra/scripts/gen-env.mjs --check >/dev/null 2>&1; then
  echo "refusing: infra/compose/.env has placeholder or missing values." >&2
  echo "  node infra/scripts/gen-env.mjs --check   # names them, prints no values" >&2
  exit 1
fi
HOOK
chmod +x .git/hooks/pre-commit
```

Check 2 is what keeps section 5 true over time: it greps the *staged* content
for a `"secret"` or `"password"` whose value does not begin with `$` — exactly
the shape of a literal somebody pasted in.

## 8. Quick reference

```bash
node infra/scripts/gen-env.mjs                    # create or top up infra/compose/.env
node infra/scripts/gen-env.mjs --check            # exit 1 if anything is generic
node infra/scripts/gen-env.mjs --example          # refresh the committed template
node infra/scripts/gen-env.mjs --rotate VAR       # replace exactly one secret
node infra/scripts/gen-env.mjs --out /tmp/x.env   # write somewhere else

python3 infra/scripts/create_users.py --dry-run             # show, change nothing
python3 infra/scripts/create_users.py                       # create + assign roles
python3 infra/scripts/create_users.py --reset-credential    # new credential for existing users
python3 infra/scripts/create_users.py --permanent           # no forced change at first login
```

Both are idempotent: running either twice changes nothing the second time.
