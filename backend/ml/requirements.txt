#
# onnxruntime is NOT pinned here — the Dockerfile installs the right variant,
# because the GPU build's version is tied to the CUDA version torch was built
# against and getting it wrong is silent, not loud:
#
#   torch cu12x     ->  onnxruntime-gpu==1.22.*   (needs CUDA 12 + cuDNN 9)
#   torch cu13x     ->  onnxruntime-gpu>=1.28
#   Apple Silicon   ->  onnxruntime>=1.20          (NOT onnxruntime-gpu)
#   CPU-only        ->  onnxruntime
#
# There is no Metal execution provider. The Apple GPU/ANE is reached through the
# CoreML EP, which ships inside the ordinary macOS arm64 `onnxruntime` wheel;
# `onnxruntime-gpu` is CUDA-only and has no arm64 macOS build at all. 1.20 is the
# floor because CoreML string provider options (MLProgram, MLComputeUnits)
# arrived there — see app/ml/gpu.py.
#
# A mismatch does not raise. onnxruntime logs a warning and silently falls back
# to CPUExecutionProvider, where the ChangeStar ViT-B takes ~13 s per 1024 px
# tile with every core pinned. Set REQUIRE_GPU=true to turn that into an error.
# For a local CPU-only install, or any Mac: pip install onnxruntime
